# PTS引け買い戦略検証

## 目的・仮説
PTSは引け値より高値で取引される傾向があるため、
「引けで買い → PTS17時台で売る」戦略が成立するか検証する。

仮説: pts_last / close の乖離率（edge_pct）が0を有意に上回り、
往復コスト（約0.2%）を超えるエッジが存在する。

## データ
- テーブル: `aukabu.pts_quotes`
- 期間: 2026-06-19 〜 2026-07-03（10営業日）
- 銘柄: 主要50銘柄（プライム売買代金上位）
- edge_pct = (pts_last - close) / close × 100

## 手法
1. 時間帯別（17:00〜23:00）の edge_pct 分布を集計
2. 17:00スナップでの日別勝率・平均リターンを算出
3. 往復コスト0.2%を控除してネットP&Lを評価

## 結果（主要指標）— コスト込み

### 時間帯別 edge_pct（17:00が最も戦略的に近い）

| 時刻 | 平均 | 中央値 | 勝率(生) |
|------|------|--------|---------|
| 17:00 | +0.06% | +0.02% | 52.7% |
| 18:00 | -0.66% | 0.00% | 48.5% |
| 21:00 | -0.39% | +0.13% | 59.2% |
| 22:00 | -0.27% | +0.11% | 60.3% |

### 17:00売り・コスト0.2%控除後の日別成績

| 日付 | 平均net | 中央値net | ネット勝率 |
|------|---------|-----------|-----------|
| 2026-06-22 | -0.05% | -0.07% | 42% |
| 2026-06-23 | -0.15% | -0.20% | 32% |
| 2026-06-24 | +0.02% | -0.09% | 42% |
| 2026-06-25 | -0.11% | -0.09% | 38% |
| 2026-06-26 | +0.05% | -0.17% | 42% |
| 2026-06-29 | -0.11% | -0.19% | 26% |
| 2026-06-30 | -0.08% | -0.11% | 40% |
| 2026-07-01 | +0.02% | -0.20% | 25% |
| 2026-07-02 | -0.69% | -0.40% | 14% |
| 2026-07-03 | -0.28% | -0.22% | 18% |

**10日間ネット勝率: 14〜42%（コスト控除後）→ 一貫して負け越し**

## 所見・結論

### ❌ 戦略は不成立

1. **エッジが小さすぎる**: 17:00の中央値 +0.02% はコスト0.2%に完全に食われる
2. **pts_lastは過大評価**: 実際の売却はbid値が必要で、pts_lastより低い（bid取得不可）
3. **流動性リスク**: PTS17時台は極めて薄く、スリッページが発生しやすい
4. **株式分割汚染**: 分割日の close は権利落ち前価格、pts_last は分割後 → 見かけ上 -75〜90% になる銘柄が混入（5801/5802/3110）。分析前にフィルタ要
5. **日別ばらつきが大**: 勝率14%〜42%と不安定。システム的に使える水準ではない

### 深夜帯（21-22時）の傾向
中央値が +0.10〜0.14%、勝率60%前後まで改善する。
ただしこれは米国市場開場（23:30〜）を先取りしたバイアスであり、
同じコストを払って売るとネットは依然マイナス。

### 次アクション（必要なら）
- 株式分割フィルタをかけた再集計（edge_pct の外れ値除去）
- 個別銘柄ベータ × 米国先物変動との相関分析
- PTS上昇銘柄（top decile）だけ翌朝のギャップとの相関（逆方向: 戻し確認）

## 参考クエリ

```sql
-- 時間帯別分布
SELECT snap_hm,
       ROUND(AVG(edge_pct)::numeric,2) as avg,
       ROUND(PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY edge_pct)::numeric,2) as median,
       ROUND(100.0*SUM(CASE WHEN edge_pct>0 THEN 1 ELSE 0 END)/COUNT(*),1) as pct_pos
FROM aukabu.pts_quotes
WHERE pts_last IS NOT NULL AND edge_pct IS NOT NULL
GROUP BY snap_hm ORDER BY snap_hm;

-- 株式分割汚染の除外例
WHERE edge_pct BETWEEN -10 AND 20
```
