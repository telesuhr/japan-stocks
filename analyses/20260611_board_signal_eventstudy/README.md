# aukabu板シグナルのイベントスタディ（前方リターン検証・コスト込み）

## 目的・仮説

auKabuデーモンが日中に検出している板シグナルに、短期の価格予測力があるかを検証する。
「板の動きでアルゴトレードできるか」の入口として、まず予測力の有無と減衰速度を測る。

**仮説（検証前に固定）:**

1. 方向つきシグナル（imbalanceShift / vwapDeviation / marketPressure）の発火後、
   シグナル方向の前方リターンは **正** に効く
2. ただし効果は速く減衰する（1分 > 5分 > 15分）
3. 2種類以上のシグナルが60秒以内に同方向で重なる「合流」は単発より強い
4. **コスト（スプレッド往復）控除後にプラスが残るかは不明** — ここが本検証の主眼（教訓2）

※ volumeSpike は方向を持たないため単独イベントからは除外し、合流の構成要素としてのみ使う。

## データ

| 項目 | 内容 |
|---|---|
| シグナル | `aukabu.signals` 2026-05-22〜06-10（14営業日、方向つき12.4万件） |
| 価格 | `public.stocks_intraday`（JQuants確定1分足、5桁コード、ts=JST naive） |
| スプレッド | `aukabu.snapshots_5sec` の銘柄別平均 spread/price |
| 銘柄 | auKabu監視銘柄（非鉄・半導体ほか、最大50） |

## 手法

- イベント: 方向つきシグナル。バースト対策として **同一銘柄×種別×方向は5分クールダウン** で間引き
- エントリー: 発火分の1分足クローズ（=発火を見てから成行で入る想定に近い保守的設定）
- 前方リターン: +1 / +5 / +15分のクローズ、シグナル方向に符号調整（bp）
- コスト: 銘柄別平均スプレッド（bp）を往復1回分控除
- 合流イベント: 60秒以内に2種類以上が同方向（daemonのCompositeWatcher相当を再構成、5分クールダウン）
- 頑健性: 期間を前半（5/22〜6/3）/ 後半（6/4〜6/10）に分割して両方で符号が揃うか確認

## 結果（主要指標）

イベント数: 方向つき単発 28,849件（5分クールダウン後）/ 合流 13,885件。
スプレッド: 中央値 3.6bp（2.0〜8.9bp）。

| シグナル | horizon | n | gross bp | t | **net bp** | 勝率 |
|---|---|---|---|---|---|---|
| composite | 15分 | 13,395 | +1.20 | 1.6 | **-2.42** | 49.4% |
| composite | 1分 | 13,395 | +0.27 | 1.2 | **-3.35** | 46.8% |
| imbalanceShift | 15分 | 18,970 | +0.60 | 0.9 | **-3.01** | 49.8% |
| vwapDeviation | 5分 | 6,104 | +1.40 | 1.8 | **-2.57** | 48.9% |
| marketPressure | 15分 | 2,722 | -2.14 | -1.4 | **-5.95** | 48.6% |

- **グロスでも有意な予測力はほぼなし**（最大でも+1.4bp・t<2）。唯一 first_half の composite 15分が +3.48bp (t=2.9) と有意だが、**second_half では -0.74bp と符号反転**＝頑健でない
- **コスト控除後は全シグナル×全期間×全horizonでマイナス**（-2.4〜-9.0bp）。勝率も全構成で50%未満
- marketPressure は後半グロスで有意にマイナス（5分 -3.71bp, t=-2.7）＝順張りでは逆効果

## 所見・次アクション

**結論: 現行の板シグナルを順張りの単独アルファ源とするスキャルピングは成立しない。**

1. 仮説1（シグナル方向に正）は棄却寄り。グロスでゼロ近辺＝板の偏りは1分足ではすでに価格に織り込まれている（教訓4の定量確認）
2. 仮説4が決定的: スプレッド3.6bpの壁をどのシグナルも越えられない。期待値+1bp台の世界で往復3.6bpを払う構造
3. 合流（composite）は単発より一貫してグロスが高く、設計思想自体は正しい方向。ただしコストを超えるには遠い

**次アクション候補:**
- 板シグナルは**執行タイミング改善（エントリー/イグジットの数十bp改善）**に用途を限定する — 予測でなく「今すぐ執行 vs 数分待つ」の判断材料としての価値は本検証では未測定
- marketPressure の逆張り利用は「後半のみ有意」の後付け発見なので、**新たな仮説として事前登録して別途検証**（このまま採用しない）
- 5秒スナップショット粒度（1分足より細かい決済）での再検証は、ティックデータ（DuckDB）と組めば可能だが、レイテンシ・約定優先順位を考えると実運用の期待値改善は限定的と予想
